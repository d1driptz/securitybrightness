# Inactive bounded synthetic payload transport

`SyntheticPayloadTransport` is a separate private transport test primitive. It
sends at most 4,096 supplied test bytes to one fixed Windows child, which checks
their exact count/digest, discards its private buffer, returns metadata and exits.
It accepts no acquisition, authority, human-review or dry-reservation evidence,
resource/path, executable, handle, callback or endpoint. No existing host,
protected reader, owner walkthrough, `/check` or v1 route selects it.

Trusted test bootstrap supplies harmless generated bytes. The Python API itself
does not attest that supplied bytes are harmless or generated; it accepts bounded
exact `bytes`. Tests use only synthetic data. This milestone establishes private
framing and failure handling, not an authorized operation or application delivery.

## Separate wire profile and original native channel

The new MAC domain and revision-1 `synthetic_transport_discard_only` mode are
separate from fixture, witness, dry-commit and dispatch-model messages. Strict
canonical JSON/base64, bounded 8,192-byte bodies, exact integer/string types,
directions, sessions, phases and chained transcripts reject malformed or extra
fields, duplicate JSON keys, collisions, substituted counts/digests and replay.
Empty data still spends a complete exchange. The binding contains internally
generated transport/fixture IDs, exact count/digest and native PID, creation time
and bootstrap session. A fixture ID is not resource identity or a pathname.

The child independently queries its current process handle and matches those
native observations before readiness. The original Windows launcher retains
atomic one-process job assignment, private inherited pipe endpoints, isolated
Python startup, restricted environment, hidden window, memory/CPU limits and
original kernel-object ownership guards. It has no selectable command or file
operation. These are lifecycle restrictions, not an OS sandbox or installed-code
attestation. The development checkout, runtime/imports, bootstrap/coordinator,
fixed child and OS remain trusted. Hostile code inside those processes or with
the ability to alter their handles/code is outside the claim.

## One attempt, uncertainty and cancellation

Each instance runs once, including failed attempts. A duplicate running call
signals cancellation of the original worker and never launches a second child.
Cancellation and final fact publication serialize on the original local lock;
only the worker owns native close/join. No registry/authority locks or human wait
are involved. There is no automatic retry, resume, renewal or returned capability.

The payload visibility barrier is recorded before the first attempted payload
frame write, including a blocked, zero or failed write. Before that barrier,
failure diagnostics distinguish cancellation from other rejection. After it,
every failure is `outcome_unknown`; it never means zero bytes reached the child.
Partial writes may complete the same bounded frame within this attempt, but
cancellation, expiry, pipe failure or receipt loss cannot start another attempt.
The diagnostic write count measures accepted frame bytes, not payload delivery.

A valid receipt remains private until strict output EOF, exact zero exit and
original native cleanup/join. Extra output, forged/truncated receipts, crashes,
hangs and uncertain cleanup withhold success. Original state, buffer, deadlines,
observations and typed evidence are rechecked after native/disposal callbacks,
immediately before sealing the final fact. Lifetimes are at most five seconds
from construction; expiry is checked before/after I/O and again after cleanup.
Existing native close may additionally wait up to one second for termination.
An unused instance owns no child; `cancel()` wipes its local test buffer.

Busy original native ownership locks are rejected without an unbounded wait.
If that lock prevents original cleanup, the attempt reports
`cleanup_confirmed: false`, remains spent and exposes no success. It must not
free a future enclosing admission slot. This standalone primitive has no shared
global admission limit, and does not promise automatic recovery of uncertain
native resources. The fixed child watchdog is ten seconds. Host composition must
retain/poison admission and deliberately solve recovery rather than reinterpret
an error as joined cleanup.

## Buffer disposal and facts

The receiving codec never returns payload bytes. Its original private bytearray
must match the binding and be wiped before a discard receipt exists; rejected
phases retire keys/transcripts even when wiping fails. The coordinator checks
its own original bytearray is empty independently of the disposal routine's
return. Exported views are zeroed, but an inability to resize/clear still rejects
confirmed cleanup. No secure erasure of immutable Python/frame/base64 copies,
kernel pipe buffers or contents already observed by the child is promised.

Corroborated immutable owner/status aliases detect a single damaged or deleted
alias and retain original cleanup targets. Foreign locks/objects are not used for
I/O or disposal. Restoring a field cannot make a spent attempt unused. This is
corruption handling within trusted code, not protection from a hostile runtime
rewriting every private anchor.

Successful frozen evidence reports only `peer_discarded`, exact count/digest and
the synthetic channel binding. It contains no data, permission or zero-release
claim, rejects implicit boolean use and returns detached inspected metadata.
Archived mutation is rejected. A new instance can send another synthetic test;
this does not establish global/durable at-most-once delivery or authority across
process restart.

## Remaining publication gates

The [original-source dry reservation](broker-live-dispatch-reservation.md) still
consumes and discards all original quarantine. This transport is not connected
to it, and no dry/model/transport fact can authorize that connection. Current
application authority and separate required human control must remain bound to
the exact original proposal, live resource, effect, operation and trusted
recipient at an irreversible one-use publication boundary. Cancellation or
revocation completed before that boundary must prevent dispatch; later changes
cannot retract bytes that have become observable.

Before a controlled generated-fixture delivery composition, the next gates are
trusted cooperating-application association, a deliberate bounded human-wait
profile, original-source/native-recipient binding, shared poisoned admission and
separate final publication/loss handling. Supported restart behavior must be
explicit. Tests of this transport do not prove those gates, immutable contents
or protection against direct Windows access. The existing fixture-reader claim
is unchanged. Application/AI intent does not equal human permission, and
SecurityBrightness remains the authorization/human-control boundary, not an
arbitrary executor or antivirus.
