# Inactive live channel with retained quarantine

`BrokerLiveChannelPublicationHost` composes the existing native fixture-retirement
profile with the original guarded fixed test-peer channel. It is a separate
diagnostic host, not selected by the protected reader, desktop/owner walkthroughs,
HTTP service, `/check` or v1. Its final operation is still a dry run that discards
the quarantine. Successful results contain terminal count/digest evidence and
zero protected bytes released, with no contents or later-operation permission.

## Original ownership across the final check

Trusted bootstrap creates the logical recipient independently of requester
proposal fields. The existing acquisition lifecycle reserves once against current
application/grant/draft/proposal/resource/effect authority and separate fresh
ALLOW ONCE evidence. DENY creates no acquisition reservation or recipient child.
Neither application authority nor human-review evidence suffices alone.

The fixed acquisition child obtains only its generated 37-byte fixture. The host
retains the original private bytearray while verifying native retirement, exact
output EOF, zero exit and joined process/job cleanup. Only then does it launch the
fixed metadata-only recipient peer, under the same single-child admission owner.
The two children are sequential. No new reservation, recipient claim or review
is created between them.

`LiveChannelPublicationCheck` accepts only the exact existing cleaned lifecycle
and its original issued recipient descriptor. It reuses the separate guarded
channel's trusted OS observation and strict witness domain; callers cannot supply
a PID, endpoint, handle, executable, observation, callback, nonce or replacement
recipient. The full action/recipient binding must match the original acquisition
token, staged summary, retirement receipt, quarantine and review. Copied or mutated
objects, replayed transcripts and rolled-back state fail closed.

The original Windows pipe/process/job ownership and process liveness are checked
around private I/O and immediately before and after the final dry run. That check
runs under helper/lifecycle/recipient/acquisition/review ownership, current
registry/ledger authority and native channel ownership locks. The same original
peer must still be live and owned while the original retained bytes are discarded.
No protected byte is sent to the peer; its protocol has no delivery message.

This helper alone does not prove acquisition-child cleanup: the lifecycle's
authenticated retirement receipt is a claim. The enclosing fixed host supplies
the actual native EOF/exit/join observations. The helper is an internal composition
primitive relying on that trusted host's existing admission ownership; it neither
acquires nor releases a second shared slot. Isolated helper tests use synthetic
resource reports explicitly, while host tests run both real fixed Windows children.

## Terminal evidence, cancellation and failure

The final attempt consumes once before invalid inputs can retry. Original source,
recipient, quarantine and host deadlines remain in force; the helper adds at most
five seconds within those original bounds. No deadline renewal bridges a retired
review or channel. These are diagnostic budgets, not a desktop human-wait policy.
The existing ten-second child watchdog and bounded native cleanup remain intact.

After the dry run, the peer receives only retirement metadata. ACK remains private
until exact stdout EOF, zero exit and confirmed joined cleanup. Terminal checks
require the original native observation/proof/ACK/codec/result identities, typed
snapshots, empty original quarantine, spent acquisition/publication state, current
authority and no superseding review. `retired_check()` returns nothing and cannot
restore a channel or authorize publication.

Cancellation is irreversible even if an event is cleared or replaced. Once a
worker starts, cancellation signals it; only that worker performs native close
and join. Callers must join before accepting shutdown status. Uncertain native
cleanup withholds results and prevents the enclosing host from releasing its
owned admission slot. A late native-cleanup fault poisons free admission if it is
still free; this is not a global mechanism to cancel another host already admitted.

All native cleanup and slot release precede the host's last metadata fence.
Additional retired-channel validation executes inside that fence, followed by
entry to a fresh authority lease and the complete original authority/source/
recipient/buffer/result checks. An already-entered lease cannot substitute for
fresh validation after a reentrant registry change. Guard
construction or validation failure also triggers original quarantine disposal.
This ordering rejects late state substitution, authority changes and bytes
reinserted after otherwise successful retirement. Foreign substituted helpers
are never invoked as if owned.

## Evidence and remaining gates

The 115 new adversarial tests (67 helper and 48 native-host cases) exercise genuine
private peer proof, native death before,
during and after the dry run, descriptor/observation/proof/ACK mutation, exact
resource/effect/application/recipient ownership, bad credentials and missing human
control, replay/duplicate workers, revoked or rotated grants, stale drafts/reviews,
buffer mutation, expiry/deadline extension, cancellation, child crash/hang/trailing
output, missing/malformed cleanup status and changes at the last metadata fence. The positive
host case observes 37 fixture bytes retained through source-child join and live
peer proof, then an empty original buffer while that peer is still live. Operator
responses are automated orchestration, not a new human demonstration.

The coordinator/bootstrap, registry/ledger, operator port distribution, development
checkout, runtime/OS and fixed peer/adapter remain trusted. The same-account child
is not an OS sandbox. Channel provenance for a fixed test peer assigned to a
registry application does not attest installed application code or human identity.
MACs do not encrypt transport; buffer disposal does not promise secure erasure of
immutable copies or immutable file contents. Direct Windows access and hostile
code inside trusted processes remain outside the claim.

The separate [inactive dry commit contract](broker-publication-commit.md) now
defines one-use metadata phases and an explicit locked consume-and-discard point
for this original witness/source. Its commit peer is synthetic in model tests;
the metadata transcript still needs a fixed native peer/host composition before
any delivery experiment. Actual publication requires a deliberate boundary for
current authority, required human control, exact resource/effect/recipient binding,
cancellation, expiry and revocation. Once bytes
cross a delivery boundary, later revocation cannot retract them; that boundary
must be deliberate and tested. A generated-fixture experiment must prove zero
delivery on every denied, failed, stale, revoked, expired, replayed or changed
request before any activation. A suitable human-wait lifecycle and trusted launch/
onboarding association for one real cooperating application also remain required.
This milestone adds no new protection claim or active delivery route.
