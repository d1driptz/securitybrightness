# Inactive generated-fixture source host

`core/broker_source_fixture_host.py` composes the first native fixture child and
the existing two-worker metadata rendezvous under one original admission owner.
It is an inactive, automated diagnostic. No existing protected reader, desktop
or owner walkthrough, `/check` or v1 route imports or selects it. ALLOW produces
only historical discard evidence, with **zero application bytes released**.

## Fixed sequence and independent requirements

The exact `BrokerSourceFixtureHost` accepts the existing registry and review
ledger plus a total lifetime of at most five seconds. It has no caller-selected
path, executable, handle, endpoint, key, adapter, callback or lifetime profile.
Trusted bootstrap distributes distinct worker and operator ports; operator
port possession is a trusted local declaration, not proof of human identity.

The original worker first acquires the existing shared one-slot admission, then
constructs and binds an exact NEW logical source. A separate fixed private
`_SourceFixtureStage` archives that original source before review begins. It
launches `_SourceFixtureChild` through the guarded Windows launcher, using the
fixed existing publication entry, isolated interpreter arguments, sanitized
environment, hidden launch and original job/process/pipe ownership. No original
source or authority guard crosses native I/O, a join or the bounded review wait.

The child creates its own harmless 37-byte synthetic fixture. Its observation
comes from the original retained Windows file handle; the displayed path is a
label, never resource identity or a selector to reopen. Authenticated frames
bind the original session and transcript. The parent retains separately the
original canonical proposal, observation, display, application/grant/review
binding and OS-observed child PID/creation time. A MAC or process observation
does not attest code, installed-application identity or human permission.

Separate required review and current application authority are both necessary.
DENY closes the first child and disposes the original local owners without
staging or launching the two later peers. ALLOW ONCE permits one bounded
acquisition into the original quarantine; it does not permit publication. The
first child must acknowledge retirement, reach strict output EOF and exit zero,
and its original native handles must be independently verified closed before
the retained-admission rendezvous can start. That rendezvous performs the
existing original-source/native-recipient association and consume/discard.
Both later workers and their genuine fixed Windows metadata children must
retire before final current authority and cleanup checks can return evidence.

## Original ownership through final release

The custody now supports an exact private fixture-stage attachment before
review, without changing its existing logical-only profile. Original typed
source, review, quarantine and first-child archives remain inside the outer
admission fence throughout the later peers and final return. A cleanup boolean
or replacement wrapper cannot substitute for original ownership.

Monotonic creation, failure and completion signals reject copied owners,
archive erasure, restored older status and attempts to release a later owner's
slot. Successful retirement retains the actual acknowledged frame digest and
the exact typed original `(0, True)` exit/input-retirement facts. Coherently
rewriting a retirement snapshot or codec phase cannot downgrade that evidence
to generic forced cleanup. First-child ownership and retirement checks repeat
after later worker callbacks, during outer release and before final return.

Cancellation signals captured original events without acquiring the host
control lock or disposing native resources from the operator thread. Only the
original worker disposes them. Original authority, source and native ownership
guards remain nonblocking. Bounded retries for private host control occur only
on the original worker, outside those guards and within the unchanged deadline.
Substituted synchronization objects never select a foreign wait or callback.

Failure always withholds association evidence and attempts disposal of known
original local owners and quarantine. Captured original review maps and IDs are
used directly; substituted review/acquisition managers receive no cleanup
callbacks. Restoring local links solely for disposal irreversibly marks failure
and never restores authority. Registry and ledger links are not repaired.
Unknown constructor or native cleanup state retains/poisons admission. There is
no reset, renewal or retry that frees an uncertain original owner. Confirmed
forced cleanup on a denial/cancellation path remains distinct from successful
protocol retirement. Timer cancellation signals are checked; timer threads are
not claimed joined, and Python/kernel copies have no secure-erasure guarantee.

## Verification and remaining gates

The 74 added tests use only generated fixtures and automated operator decisions.
They cover real three-child ordering and admission retention, separate authority
and review, credential/permission/revocation changes, replay, concurrent starts,
bootstrap collisions, copied/coherent archives, mutated native observations and
handles, malformed displays, byte limits, buffered-stage failure, crashes,
hangs, corrupt/duplicate/extra protocol output, late release mutation, foreign
managers/locks and known-original disposal. Fault tests assert that their genuine
target phase was reached. The combined focused suite passed 250 tests in
147.163 seconds, with no skips. Complete verification is recorded in
[the development log](DEVELOPMENT_LOG.md). The workspace-only Windows temporary
directory ACL harness is not shipped. Runtime `security_events.json` is excluded.

A separate [bounded-wait native prerequisite](broker-wait-native-profile.md) now
defines distinct wait/acquisition lifetimes and a fixed new fixture child. This
source host does not select it: deliberately composing exact-resource human
review, current registry/lifecycle state and original admission across those
lifetimes remains a separate gate. This diagnostic retains its exact five-second
contract; it does not accept the separate 30-second desktop-review subclass or
silently extend any original resource deadline. It is not yet an interactive
owner demonstration.

Trusted cooperating-application association and exact original-source/native-
recipient payload publication remain separate gates. Before controlled delivery,
partial writes, crashes, lost receipts, revocation/expiry and restart outcomes
must have explicit tested semantics. Historical review/discard evidence never
activates them or grants future authority.

The parent coordinator, trusted bootstrap, runtime/checkout, fixed entries,
native adapter and Windows remain trusted. This is no sandbox against hostile
code inside that trusted process, no prevention of direct Windows access, and
no immutable-content or globally durable exactly-once guarantee. The existing
fixture protected-reader path remains the only narrow protected-operation
claim. Application/AI intent does not equal human permission. SecurityBrightness
remains the authorization/human-control boundary, not an arbitrary executor or
antivirus.
