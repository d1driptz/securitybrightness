# Inactive fixed native-binding child

`core/broker_binding_entry.py` and the internal `_BindingMetadataChild` launcher
add a separate metadata-only child profile. No existing host, desktop, protected
reader, `/check` or v1 route selects it. It never reads or delivers file contents.
All resources are generated by the existing fixed fixture owner.

The launcher inherits the existing isolated Python startup, fixed entry path,
minimal environment, exact inherited private pipes, hidden window and atomic
restricted job attachment. This is still a trusted same-account process, not a
reduced-token sandbox against hostile code running under that account.

## Transcript and native checks

The child authenticates bootstrap and sends its PID-bound readiness message. It
accepts the existing initial proposal message and emits a newly owned native
observation. It then switches to the separate acquisition-binding wire domain;
the old metadata `verify` command cannot finish this profile.

The binding context must match the original application, exact proposal identity,
decision, locally retained session/owner/token, volume/file ID, observed size,
byte limit, operation and recipient. Native inspection checks the exact locally
issued observation against the retained handle. The child reconstructs the
display from original proposal/native facts and the supplied grant/draft claims
and compares its digest. Paths remain displayed labels, not resource identity.

Grant, draft and review fields received over IPC are **claims**, not current
authority or independently authenticated human review. The child has no registry
or human-authentication channel. Its `bound` reply means that local resource and
request metadata matched; it must never be treated as executable permission.

On `retire`, native inspection and one-use native verification run again. On
`cancel`, ownership closes without a content operation. Both paths require input
EOF, close the fixture session, and only then emit the exact zero-byte denied
retirement acknowledgement. Malformed input, failed inspection or cleanup, a
truncated command or trailing input produces no successful acknowledgement.

The binding codec has its own at-most-five-second deadline starting before the
observation is sent. An independent ten-second child watchdog handles blocked
pipe reads that a codec timer cannot interrupt. The native delete-on-close handle
and kill-on-close job remain responsible for crash/parent-loss cleanup. Timers
are bounded best-effort scheduling, not hard real-time guarantees.

## Verified composition and limits

The 25 new tests launch the real fixed child and use the existing live coordinator
review/reservation model. Test orchestration supplies the operator response; this
is not a human walkthrough. Successful retirement tests withhold the acknowledgement
until exact EOF, zero exit, job cleanup and fixture deletion, then check/consume
current coordinator review evidence. Revocation, credential rotation, changed
drafts and expiry prevent that final consumption despite a valid child reply.

Other tests cover substituted resource/application/proposal/effect/session/display,
changed grant claims without a matching display, replay, cross-domain commands,
truncation, trailing input, pipe loss, cancellation, no scope, missing operator
review, native verification failure, cleanup failure, process crash and independent
watchdog deletion. Fault injection replaces the child entry only inside tests;
the product launcher has no caller-selected entry argument.

The child milestone supplies the fixed child and integration tests. The subsequent
inactive binding host owns cancellation, shared admission, child joining and
poisoned admission on uncertain cleanup, and withholds results until final
authority/freshness validation. No raw child acknowledgement may bypass those
checks. Neither component is connected to an owner-facing integration.

The native retirement receipt cannot authorize a later read: the resource has
already been retired. Actual acquisition still requires a deliberate live one-use
transition, quarantine and an independent final publication check. The original
fixture-only protected-reader claim remains unchanged.

The separate [inactive binding host](broker-binding-host.md) now implements the
coordinator ownership and final-check boundary described above. It remains
unconnected to any desktop or active authorization route and performs no reads.
