# Inactive native retirement with retained quarantine

The separate `PublicationNativeFixtureAdapter`, fixed
`broker_publication_entry.py` child and `BrokerPublicationDiscardHost` compose
native fixture acquisition with the recipient-bound publication draft. No existing
desktop, owner walkthrough, protected-reader, `/check` or v1 route selects them.
There is no application byte-delivery API, caller-selected file, executable,
recipient address or operation dispatcher. Public results release zero bytes.

The trusted worker authenticates current application authority and an exact live
proposal/draft before starting a fixed private child. It creates and retains an
exact logical recipient owner separately from requester data. The child creates
only the built-in harmless 37-byte fixture, atomically, and emits observation
metadata derived from the original noninherited native handle. A path remains a
display label. Ordinary competing read/write/delete opens, links/reparse points,
unsupported volumes, identity changes and descriptor reuse are handled by the
existing narrow original-handle adapter contract.

Explicit DENY kills and joins the child without creating an acquisition
reservation. ALLOW ONCE evidence permits one staging attempt only when current
grant activation, application/proposal/draft/version, human-review display and
resource/effect binding are all fresh. Application authority alone cannot stage;
review evidence alone cannot bypass revoked or changed authority. The typed
recipient application/session/nonce/revision is authenticated in the separate
wire envelope, never supplied as an authority field in the proposal.

The native profile validates the original opening, exact resource/application/
proposal/decision/effect and supported recipient revision before one bounded read
using the original descriptor. It repeats original-handle metadata and proposal
checks after reading and frame generation. Logical recipient fields are trusted
coordinator claims, not an independently observed recipient channel. A signed
different nonce for the same app cannot pass the parent's original envelope.
The adapter has no current registry lease: revocation can race a request already
sent into private native acquisition. The coordinator rejects stale authority
before accepting staging, at retirement and final checks. No global prevention
of every internal native read is claimed.

Coordinator bytes stay in the original private quarantine while the child
validates and retires native ownership. The child requires exact input EOF,
closes its original native handle before emitting an authenticated retirement
claim, exits its context and repeats snapshot/deadline/cleanup checks before
writing the acknowledgement. Substituted native-owner or codec objects are not
closed as if they were owned; original ownership is cleaned up and the substitution
remains terminal evidence that invalidates completion. Cleanup cannot hide it.

The host keeps the acknowledgement private through exact stdout EOF, zero exit,
and confirmed process/job cleanup. Only then does it accept the retirement claim
and call the separate one-use final publication check with the exact recipient
descriptor. Quarantine remains intact through that process-cleanup boundary;
the final dry run disposes of all bytes and retires source and recipient. Signed
claims alone are never substituted for process liveness or cleanup checks.

All remaining cleanup and shared-admission release precede a final metadata
return fence. The fence checks current registry/authority/draft/review/proposal,
the exact decision/display/token/summary/receipt and recipient identities, complete
context binding, original host/source/recipient/wire deadlines, closed keys/state,
original empty quarantine and cancellation. Post-cleanup reinsertion or replacement
of buffered bytes rejects the result and disposes of quarantine again. Cleanup
uncertainty withholds the result and reports failed cleanup status; free admission
is poisoned rather than allowing a retry.

The total diagnostic budget remains at most five seconds. Trusted operator and
worker ports stay separate, and callers cancel and join the worker to confirm
shutdown. The fixed child has an independent ten-second watchdog. Existing
isolated Python startup, fixed entry/cwd, minimal environment, private inherited
pipes, hidden process and atomic bounded job restrictions are unchanged. A native
call holding the adapter lock cannot block the independent process watchdog or
the parent's job termination. Both interruption paths are tested with an actual
child blocked during acquisition and confirm fixture deletion.

The 119 new adversarial tests comprise 49 native-profile and 70 host/child tests.
They cover real fixed-fixture acquisition, private retention through cleanup,
zero-byte final disposal, missing authority/review, version/domain/type/identity
mismatch, replay/concurrency, malformed input, native/frame/context mutation,
foreign ownership preservation, revocation/rotation/draft/recipient changes,
crashes before and after buffering, blocked acquisition, independent watchdog,
trailing/nonzero/hung output, cleanup uncertainty, and final slot-release mutation.
Scripted responses are automated orchestration, not a new owner walkthrough.

The coordinator, trusted operator bootstrap, registry/ledger, launcher, runtime/OS
and fixed child adapter remain trusted. The same-user child is not a restricted
token sandbox or protection against hostile code in either trusted process.
HMAC authenticates private transport and does not encrypt it; wiping does not
promise secure erasure of immutable interpreter or transport copies. No immutable
file-content or direct Windows access-control guarantee is added.

## Next gate before application delivery

Native/process retirement for this retained-check profile is now tested. The
recipient is still a logical binding, not a real authenticated application
channel. The separate [inactive fixed-peer channel witness](broker-recipient-channel.md)
tests trusted launch, original Windows pipe/process ownership, current binding,
one-use proof and joined retirement for a cooperating test peer. It does not
activate a live recipient channel in this host; its retired result cannot supply
one. Application names, PID strings, path labels or stored review receipts cannot
establish a channel. Live composition remains a separate gate.

Actual publication still needs one fixed bounded delivery operation with an
explicit final linearization point under current authority, human control,
resource/effect/recipient binding, revocation/expiry and cancellation checks.
It must consume once and dispose on every failure. Only a separate generated-fixture
experiment should exercise delivery first, demonstrating that DENY/replay/stale/
revoked/expired/changed requests yield zero bytes through that protected path.
The owner UI also needs a deliberately tested human-wait lifetime; no deadline
mutation or retired token may bridge it. Existing protection claims remain unchanged.
