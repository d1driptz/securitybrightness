# Inactive fixed native dry publication commit

`BrokerNativePublicationCommitHost`, `NativePublicationCommitCheck` and its fixed
`_PublicationCommitPeer` compose the existing generated-fixture source with an
actual private Windows commit exchange. This is a diagnostic prerequisite:
**every protected byte is discarded and zero protected bytes are delivered**.
No active service, desktop/owner walkthrough, protected reader, `/check` or v1
route selects this host. There is no caller-selected executable, endpoint,
application peer, acquisition target or delivery callback.

## Original ownership and bounded transport

The source child creates only the existing harmless generated fixture. It stages
the bounded data into the original coordinator quarantine, retires its retained
resource and reaches strict EOF, zero exit and joined cleanup before the commit
peer launches. The enclosing host retains one shared admission slot across both
sequential children. It does not create a second human review, reservation or
logical recipient to bridge the phases.

The fixed peer inherits the original hidden isolated Python startup, minimal
environment, atomic kill-on-close Job assignment, non-inheritable private pipes,
original process handles and independent kernel-object guards. PID and creation
time are queried through the original process handle; neither a supplied PID nor
a normalized pathname establishes identity. The peer independently queries its
own current-process handle and checks that the commit envelope matches that
identity, the bootstrap session and the complete original witness binding.

The channel first performs the existing authenticated witness exchange. The
separate commit MAC domain then carries PREPARE, READY and DRY_COMMIT metadata,
followed by witness retirement. The peer requires exact input EOF before emitting
its commit receipt and witness acknowledgement, then exits. Frames remain bounded
and canonical; the strict envelope binds application/proposal/resource/effect,
logical recipient, staged count/digest, commit ID and original channel/session.
It accepts no authority, content, endpoint or extra operation fields.

Coordinator waits occur outside registry/ledger locks. Checks before and after
each bounded pipe operation renew original ownership, native guards, clocks and
authority freshness. Original source, recipient, quarantine and host deadlines
are never extended. The helper is capped at five seconds and the fixed peer has
an independent ten-second watchdog. These diagnostic lifetimes are not a usable
human interaction lifetime or an authority renewal mechanism.

## Explicit dry boundary and separate terminal gate

The original draft's locked commit boundary requires current application
authority, the original separate human review, the exact proposal/recipient and
the still-live original native peer. The first attempt burns before invalid
credentials can retry. It irreversibly consumes the original source and discards
all staged bytes before sending dry-commit metadata. Neither application
authority alone nor a fresh review record alone can cause this transition.

Both returned frames remain private until strict output EOF, exact zero exit and
guarded original native close/join succeed. The witness acknowledgement is
validated first. A separate native-only terminal gate then checks the original
commit transcript, issued zero-release result, empty original buffer, retired
channel and fresh registry/lifecycle authority before sealing the receipt. The
old synthetic draft retains its alive-only finish rule; it cannot stand in for
native retirement evidence. Native receipts cannot restore a consumed source or
authorize another operation.

Cancellation only signals the original worker. That worker owns native cleanup;
failure also closes the original draft and independently wipes its original
buffer. Original commit key and timer disposal still run if changed draft owners
prevent normal closure. Foreign owner/channel objects are not dispatched as owned
resources; mutated quarantine bytearrays are wiped. Uncertain
native cleanup withholds even zero-byte metadata and retains or poisons shared
admission. Cleanup and receipt validation are followed by the enclosing host's
separate fresh-authority fence; revocation during validation or slot release must
not be hidden by an earlier registry lease.

## Scope and remaining gates

Real Windows tests exercise both private transcript domains, original channel
identity, missing phases, input/output EOF, malformed/injected fields, replay,
mutations, stale authority, cancellation, crashes, hangs and cleanup uncertainty.
Positive host tests use the actual generated source fixture; lower-level helper
tests supply model resource reports. All operator decisions in these automated
tests are orchestration, not a completed owner demonstration.

The peer proves receipt of exact dry metadata through the original launched
channel. It does not prove application byte delivery, installed application code
identity, immutable file contents, secure erasure of interpreter copies, hostile
trusted-process isolation or protection against direct Windows file access.
Coordinator/bootstrap, registry/ledger, operator-port distribution, development
checkout, runtime/OS, fixed source adapter and peer remain trusted. The logical
application assignment comes from trusted bootstrap, not from code attestation.

The separate [dispatch and loss model](broker-dispatch-model.md) tests an
irreversible in-memory reservation and explicitly unproven receiver claims.
The new [original-source dry reservation](broker-live-dispatch-reservation.md)
binds that model to current authority/source and recipient in the separate live
synthetic-commit profile, and consumes/discards without delivery. This fixed native
composition remains unchanged. A separate inactive [synthetic payload transport](broker-synthetic-payload-transport.md)
now tests bounded fixed native framing/private transport and discard, without
connecting to authority or the original quarantine. Live publication binding
and shared admission remain gates: later revocation cannot retract delivered
bytes, and a lost receipt must not permit another delivery. Trusted real-application
onboarding, deliberate human-wait lifetime and a controlled fixture-delivery
experiment remain separate prerequisites. No dry receipt may activate them.
Application/AI intent does not equal human permission; SecurityBrightness remains
the authorization and human-control boundary, not a general executor or antivirus.
