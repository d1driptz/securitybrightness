# Inactive original-source/native-recipient association

`SourceNativeAssociationDryRun` binds an existing live, ready dry-commit source
to one separately launched fixed Windows metadata peer. It authenticates the
current original application, requires the original separate human control,
consumes the source once and discards its entire quarantine. It sends no source
payload and introduces no resource acquisition or file-access operation.
Successful evidence reports `associated_discarded` and zero protected bytes
released; it cannot authorize a later operation.

No protected reader, service, desktop or owner walkthrough, `/check` or v1 path
selects this primitive. The existing verified fixture-reader claim and existing
native dry-commit host remain unchanged. This is an inactive prerequisite for
source-to-recipient publication, not an activated cooperating-application read.

## Two original native channels, without rewriting the source

Trusted bootstrap supplies the coherent original `PublicationCommitDraft` owner
graph. The primitive captures the existing authority, lifecycle, proposal,
resource/effect, quarantine, logical recipient, grant and application fingerprint.
It does not accept a caller-selected native endpoint, executable, path, callback,
observation, receipt or replacement source binding.

The original canonical source dry-commit envelope is embedded unchanged in
`source_commit_json`. Its nested source channel continues to describe the
original live witness. A separate `recipient_channel` describes the new fixed
`_SourceAssociationPeer`, using PID and creation time observed through its original
process handle, plus a fresh private bootstrap session. The source and new
recipient channel identities must differ. A path label or caller-supplied PID
cannot establish this identity.

The fixed child inherits the existing private pipes, guarded original native
objects, hidden startup with isolated Python options and kill-on-close job lifecycle. It independently
queries its own current-process handle and checks the exact outer PID, creation
time and session before producing its `associated_ready` proof. Those checks bind the launched
channel; they do not attest installed application code or authenticate a real
cooperating application. The logical application assignment still comes from
trusted bootstrap. The development checkout, runtime/imports, coordinator,
registry/ledger, fixed peer and Windows remain trusted.

## Separate bounded metadata transcript and current authority

`SourceRecipientAssociationExchange` uses its own MAC domain and revision-1
`source_native_association_discard_only` mode. Its four phases are an exact
request, `associated_ready`, `source_discarded` and `associated_retired`.
Canonical ASCII source JSON is checked against the unchanged source commit
contract. The outer grant UUID must match the source context, and the original
grant fingerprint is captured by trusted composition. IDs and sessions cannot
collide with each other or the original source identifiers.

The codec enforces bounded canonical framing, exact types/fields, session and
chained phase binding. Unsupported authority, data, path and operation fields,
version mismatch, mutations and replay retire the endpoint. The original codec
lock is checked before acquisition, so a substituted foreign lock is not entered.
The pure wire evidence is an authenticated claim, never current authority,
resource truth, source-disposal proof or delivery permission by itself.

The composition rechecks the original application authentication, grant,
registry and lifecycle freshness, required human review, exact proposal/effect,
recipient and quarantine around native operations. Application authority alone
and human-review evidence alone each fail. No requester-controlled record can
manufacture or transfer the original source authority.

With both original guarded channels live, the existing one-use reservation
consumes and discards the source under the captured authority serialization.
Only then does the new child receive the metadata retirement claim. Failure
before or after this transition leaves the accepted attempt spent; restoring a
field, replaying a frame or constructing another wrapper cannot restore the
consumed source. No receipt or dry fact exposes a payload or delivery capability.

## Lock boundaries, cancellation and disposal

Pipe operations and worker joins run outside the captured original source,
registry, review, codec and old native ownership locks. The new peer's own
native guard protects its cleanup. Calling from an old host callback that still
holds those locks is rejected. Source validation uses bounded, nonblocking
acquisition of captured original locks; contention fails closed instead of
waiting through a registry/coordinator cycle. The diagnostic lifetime is at
most five seconds and never extends the original source deadline. It is not a
usable human-wait lifetime or an authority renewal mechanism.

Bootstrap rejection also signals and spends captured original owners before
nonblocking disposal. A newly contended lock never selects an unguarded blocking
fallback. Private model keys are retired even on cancellation before native
startup; cleanup uncertainty remains explicit rather than reporting success.

Cancellation signals captured original workers. The original witness worker
alone owns close/join of its old child; the new association worker alone owns
close/join of the new child. The association cannot join the original worker
while source authority is held, and its returned fact does not independently
claim that the old worker has already joined. Captured original references are
used for disposal; foreign object substitutions cannot redirect cleanup.

A new peer receipt stays private until strict output EOF, exact zero exit and
guarded original new-child cleanup/join succeed. Native cleanup, local model/key
disposal and original source freshness are separately checked. Evidence fields,
native ownership, empty original quarantine and current authority are rechecked
after disposal and again while sealing the historical result. Reentrant archive
or cleanup mutation cannot turn a provisional fact into accepted success.

Uncertain, busy or no-op cleanup withholds success and reports unconfirmed cleanup.
A future enclosing host must retain or poison shared admission on uncertainty;
this standalone primitive provides no active shared admission, automatic
recovery or durable restart guarantee. Immutable corroborated owner/status
references detect a single damaged alias. They are corruption checks within
trusted code, not protection from hostile code rewriting every private anchor.

Frozen successful evidence contains detached metadata, zero released bytes and
no authority or payload. Implicit boolean use raises. After completion it is a
historical fact: later revocation does not rewrite history, and the fact cannot
renew freshness, reopen the source or authorize a later read. Archived mutation
is rejected. Interpreter copies are not claimed to be securely erased, and file
contents are not claimed immutable.

## What the tests establish and what remains

The test composition uses genuine old and new Windows native channels. Resource
observations, operator decisions and old model readiness are synthetic test
orchestration. The old worker is paused outside its authority callbacks so the
new gate must acquire and check original current authority itself. This pause is
not a production host rendezvous or a completed owner demonstration.

Adversarial cases cover invalid or substituted applications/credentials,
authority and lifecycle changes across proof, consumption, acknowledgement,
cleanup and final sealing; replay; owner/observation/state mutation; busy locks;
source or recipient death; extra output; nonzero exit; cleanup uncertainty; and
attempts to report protected bytes from a zero-byte fact. Neither codec nor
composition reads or publishes an original payload.

Verification: 158 added tests (57 protocol and 101 native composition). The
complete workspace suite passed 2,315 Python tests and all 8 scanner tests with
no skips. The existing workspace-only temporary-directory ACL harness is not
shipped. Existing production paths and test assertions were unchanged; runtime
`security_events.json` is excluded.

Before a controlled generated-fixture delivery experiment, the remaining gates
are a deliberate resumable host rendezvous with bounded shared poisoned
admission, trusted real-application association, a deliberate bounded human-wait
profile, and exact original-source/native-recipient payload publication and loss
handling. The irreversible publication boundary must preserve current authority,
separate human control and exact resource/effect binding. Lost receipts must not
permit another delivery; later revocation cannot retract bytes already visible.

This milestone establishes a native metadata association and original one-use
consume/discard, not application delivery, immutable contents or protection
against direct Windows access or hostile trusted-process code. Application/AI
intent does not equal human permission. SecurityBrightness remains the
authorization and human-control boundary, not an arbitrary executor or antivirus.
